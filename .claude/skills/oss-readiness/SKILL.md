## Licence is a human decision

Do not pick one unilaterally. Present the trade — permissive (MIT/Apache-2.0) versus
copyleft (AGPL-3.0, relevant for a hosted web app) — and let the owner choose. It is the
hardest decision to reverse once other people have contributed, because reversing it needs
every contributor's agreement.

## Writing CONTRIBUTING

Generic templates produce broken first pull requests. This repo's non-obvious facts, all
of which belong in it:

- npm workspaces: Next.js app at the root, `packages/shared`, `mobile` (own tsconfig and
  eslint config), `src-tauri`
- root `tsc --noEmit` **excludes** `mobile` and `src-tauri` — three separate verification
  command sets, listed in `AGENTS.md`
- `mobile/android/` is generated by `expo prebuild`; changes go in `mobile/plugins/`
- the five hard invariants, linked, with the invariant script as the way to check them
- docs and commit messages in English; user-facing UI strings in Vietnamese
- shared logic belongs in `packages/shared` so all three shells stay in sync
- new exports must be added explicitly to `packages/shared/src/index.ts` or they fail at
  runtime rather than at typecheck
- Android builds on Windows need `LongPathsEnabled=1` **and** ninja ≥ 1.11 (see the
  `release-android` skill) — this blocked development for a full day and will block a
  contributor for longer

## SECURITY.md is not boilerplate here

This repo handles OAuth tokens for three storage providers, a YouTube account, encrypted
token columns, and an irreplaceable signing keystore at
`mobile/credentials/vong-release.jks`. Provide a real private disclosure route, state that
the keystore must never enter git, and confirm `.gitignore` covers credentials and
`.env.local`.

## Committed binaries

Deleting the APK in a new commit does **not** remove it from history — every clone still
pays for it forever. Removing it from history means rewriting it (`git filter-repo`), which
rewrites every commit hash. Recommend doing it *before* the repo is public and other people
hold clones; afterwards, it is usually not worth the disruption. Either way, add
`*.apk`/`*.exe` to `.gitignore` so it cannot recur.

## Issue and PR templates

Bug template must ask for the **shell** (web/Android/Windows) and app version — the same
symptom has different causes per shell, and without it every report costs a round trip.

PR template should ask which verification commands were run, on which shells, and whether
any hard invariant was touched.

## Triage

Per issue: reproducible or not, which shell, which subsystem, invariant touched. Bugs go to
`cross-shell-qa`; feature requests go to `product-owner` for scoring. Never write a feature
request straight into `backlog.md` — an unscored row corrupts the ordering that the whole
backlog depends on.
